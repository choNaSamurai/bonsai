# ADR-0004: Процедурний меш гілок + інстансинг листя; анімація у вершинному шейдері

- **Статус**: Proposed
- **Дата**: 2026-10-03
- **Автор**: Unity Architect, Technical Artist
- **Пов'язані задачі**: PA-103, PA-203, PA-305

## Контекст
Оригінал: Single-pass `TreeRenderBox`, 4 `drawPath` (яруси товщини), 1 `drawRawAtlas` для листя, zero-alloc буфери, `rain_sheen.frag`, світлячки як частинки. Ціль — 120 FPS без GC.

## Рішення
- **Гілки**: один `Mesh` на дерево; сегменти — стрічки вздовж кубічних Безьє з конусністю та круглими з'єднаннями; ярус товщини і «гнучкість» — у вершинних атрибутах. Перебудова лише при зміні `TreeGraph.Version` (через `Mesh.SetVertexBufferData` з преалокованих `NativeArray`). → **1 draw call**.
- **Листя/квіти/бруньки**: `Graphics.RenderMeshInstanced` або комбінований quad-меш з атласом → **1 draw call**. Skip при `LeafScale < 0.02`.
- **Вітер, дихання Дзен, нахил листя при посусі (−12°)** — у vertex shader (Shader Graph, Sprite-Lit) за параметрами `_WindTime`, `_Breath`, `_Droop`. CPU не рухає вершини щокадру.
- **Rain sheen** — параметр `_Wetness` у шейдері листя. **Світлячки** — `ParticleSystem`.
- **Знімок для віджета/Polaroid** — окрема камера → RenderTexture → `AsyncGPUReadback`.

## Розглянуті альтернативи
| Варіант | Плюси | Мінуси |
|---|---|---|
| `LineRenderer` на кожну гілку | Просто | 200 draw calls/об'єктів, погана конусність і стики |
| SpriteShape | Готовий інструмент | Не для деревоподібних графів, важкий |
| Скелетна анімація (2D Animation) | Гнучкі кістки | Надмірно, складно генерувати процедурно |
| Перебудова мешу щокадру | Проста анімація | CPU/GC-вартість, батарея |

## Наслідки
- + ~2–4 draw calls на всю сцену з деревом.
- − Потрібен власний mesh-builder і Shader Graph — найризиковіша технічна частина Спринту 1; закладено Spike у PA-103.

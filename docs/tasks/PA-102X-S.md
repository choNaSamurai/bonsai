## Контракт сцени й камери (з ескізу)
- Одиниці — пікселі кадру 680×480 (масштаб 1). Осі ескізу: x — праворуч, y — вгору, z — **до глядача** (правобічна). Unity — лівобічна: `z_unity = −z_sketch`.
- Ортографічна камера з нахилом `SE = 0.28`, `CE = √(1−SE²)`: екран `sx = 340 + x`, `sy(зверху) = 400 − (y·CE − z·SE)`; напрям погляду `D = (0, −SE, −CE)`; глибина `t = dot(P, D)`, нормована `(t − (−260)) / 740`.
- Світло за замовчуванням (`env` у golden): `L = (−0.4482, 0.7324, 0.5126)`, `sunC = (1, 0.93, 0.82)`, `amb = (0.85, 0.9, 1.0)`; тонмап `1 − exp(−1.35·c)`, гама 1/2.2. Формули освітлення, кори, ґрунту, горщика, листя — у `FS`/`LFS` ескізу; переносяться як є (власні unlit-шейдери, не `Light2D`).
- Порт генератора зберігає **ту саму розкладку масивів** (`DAT`, `CB`, `GM`, `PE`, `LEAF`, `XLEAF`) — це контракт між генератором і рендером. Значення, які ескіз зберігає у `Float32Array`, порт теж зберігає як `float` у тих самих місцях (від цього залежать порівняння на кшталт `LEAF[o+7] > 0.3`).

## Acceptance Criteria — фаза 1 (у редакторі, Metal)
- [x] **G1** (GP) Порт генератора: для всіх 90 golden-конфігурацій лічильники збігаються точно; `P`, `T`, `DAT`, `CB`, `GM`, `PE`, `LEAF`, `XLEAF` — у допуску 1e-3 (абсолютна, одиниці кадру) або 1e-4 відносна; EditMode-тести зелені. → ✅ 2026-10-09: 90/90, f32-масиви біт у біт, f64 ≤ 3e-14; 102/102 EditMode; генерація найважчої сцени ≈ 5 мс (редактор, Mono).
- [x] **G2** (UA) Меш деревини B\*: стовбур + корені + гілки 3 рівнів — трубки вздовж тих самих B-сплайнів/конусів, коміри на стиках, основа (стик стовбура з коренями) — патч ізоповерхні (Surface Nets) або обґрунтована альтернатива; без видимих кілець, швів і «накладань» (вимоги, які вже виконує ескіз).
- [x] **G3** (UA) Запікання B1 (синхронно при зміні дерева): м'яка тінь, AO, напівпрозора тінь крони (`folT`) — тим самим SDF-кодом ескізу (HLSL-порт), per-vertex.
- [x] **G4** (UA + TA) Процедурні кора за породою (з рельєфом), ґрунт із мохом, горщик (3 типи: токонаме / куро / селадон) — функції ескізу від світової позиції.
- [x] **G5** (UA + TA) Листя: один меш квадів, процедурна форма в шейдері (пальчастий / яйцеподібний / хвоя), двобічне світло й просвічування, depth-тест проти деревини; Ямадзакура/Куромацу з `XLEAF` — лише якщо вистачає часу (у липні вони приховані).
- [x] **G6** (UA) Тест глибини в URP 2D Renderer (Metal): листя ховається за стовбуром і навпаки; висновок — чи лишається 2D Renderer.
- [x] **G7** (UA) Харнес: batchmode рендерить PNG 1360×960 RGBA з тією самою камерою для ≥ 27 конфігурацій (3 породи × `moyogi`/`chokkan`/`shakan` × `t` 0.3/0.6/1.0, насіння 3) + аркуші «ескіз | Unity»; **IoU альфи ≥ 0.92** для кожної (таблиця); заміри в редакторі (інформативно): час побудови мешу, час запікання, трикутники, кількість листя.
- [x] **G8** (власник) Візуальний гейт K12 — **«так», 2026-10-09**: «так» / «ні» на аркушах. — аркуші: `.agent-workspace/pa102xs/unity/sheet_*.png`; звіт [PA-102X-S-phase1-2026-10-09](../qa/reports/PA-102X-S-phase1-2026-10-09.md): IoU 27/27 ≥ 0.92 (мін 0.9818, сер. 0.9854); сцена `Assets/_Project/Spikes/PA102XS/Scenes/PA102XS_Spike.unity`.

## Фаза 2 — рішення власника 2026-10-09
- **Трикутники деревини** (фаза 1: 129–144 тис. quality / 66–72 тис. budget проти оцінки ADR 20–35 тис.): спершу заміряти K1 на пристроях, потім вирішувати — LOD тонких гілочок чи перегляд бюджету ADR-0011.

- **Горщик**: параметричний меш (TA + UA) замість Surface Nets.
- **Пристрої**: моделі iPhone і Android — чекаємо від власника.
- Інше з фази 1 до фази 2: look-dev TA (кора, мох, глазурі), рішення «маска з атласу чи процедурне листя», запікання — проєкція один раз, горщик раз на горщик, часткове перезапікання після зрізу.

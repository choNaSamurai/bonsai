## User story
Як гравець, я хочу, щоб дерево, яке я терпляче стилізую секатором, з часом стало саме тим бонсаєм, що на ключовому арті, — S-подібний товстий стовбур із корінням у моху, шість ярусних подушок із повітрям між ними й купол, — щоб мій догляд мав видиму, впізнавану мету.

## Acceptance Criteria (вимірювані)

**Позначення.** «Styled» = посадка → онбординговий зріз → G = 1, vigor 1, bendBias 0 → `PruneToStyle` (BALANCE §1.3.7) на Д20, 30, …, 120; виміри — **одразу після стилізації** в дні Д80, Д90, Д100, Д110, Д120. «Фікстура» = seed `20261004`; «30 сидів» = 1…30. Рендер — прототип GrowthPreview, Textured, Metal, кадр 768×1376 з горщиком 92 units, вирівняним як у референсі (зовнішній передній край 101…667 px, верх горщика y = 1068 px від верху; TD-028).
**Маска дерева**: пікселі кори, коріння й листя з α ≥ 0.5 у зоні y < 1068 px (без горщика, ґрунту, фону). **Маска референсу** — фікстура `Art/Runtime/Preview/ref_mask_l2_momiji.png` (і `ref_mask_night_kuromatsu.png`; рішення оркестратора — лишаються там, не в Tests/Fixtures): пікселі `realism_l2_painterly.jpg` / `concept_night.jpg` у тій самій зоні з відстанню до кольору фону > порогу; маску один раз готує TA, власник переглядає PNG.
**IoU** = |A ∩ B| / |A ∪ B|, рахується для маски і для її дзеркала відносно центру горщика, береться **максимум** (`TierPhase = −1` дає дзеркальне дерево — це законний варіант).

## Нотатки / Пропозиції

### Game Designer (крок 1, 2026-10-05)
**Розрахунки (Momiji, G = 1, bendBias 0)** — деталі в BALANCE §1.3:
- *Висота*: ланцюг 38 + 22.5·cos30° (19.5–19.8) + 20.3·cos26.4° (18.1) + 18.2·cos23.2° (16.7) + 16.4·cos20.4° (15.4) ≈ **108**; вісь крони 7.8 + 6.7 (≤ 2 вузли Styled) + купол листя ≈ 8 → **H ≈ 130** → H/P = 130/92 = **1.41**.
- *Товщина*: `th0(D) = 24 − 20·e^{−0.0104·D}` (ТЗ, без змін): Д20 7.6 · Д40 10.8 · Д80 **15.3** · Д120 18.3 → th0/H Д80 = **1/8.5**, Д120 ≈ 1/7.1 (дозволено AC2). З розширенням `F` = 0.25 + 0.70·0.565 = 0.65 → 25.2 → **1/5.2**.
- *Темп висоти*: затримка 6 + 3k (k1 9, k2 12, k3 15, k4 18, крона 21) + лаг вибору → k2 ≈ Д5, k3 ≈ Д17–20, k4 ≈ Д32–36, c1 ≈ Д50–55 → H: Д10 ≈ 72, Д20 ≈ 84 (**0.65**), Д40 ≈ 112, Д80 ≈ 127–130.
- *Яруси Styled*: висоти кріплення 26.6 · 36.1 · 54.8 · 73.2 · 90.1 · 105.7 = 0.20 · 0.28 · 0.42 · 0.56 · 0.69 · 0.81 H (референс 0.21 · 0.29 · 0.44 · 0.54 · 0.64 · 0.71 · 0.79); сторони −,+,−,+,−,+.
- *Вигини*: кути сегментів 10.5 · 30 · 26.4 · 23.2 · 20.4° з чергуванням; стики x = 0 → 6.9 → −4.3 → 4.7 → −2.5 → 3.2 → 4–5 змін знаку кривини на C1, розмах ≈ 0.09 H.
- *Ширина*: нижній ярус 21·sin62° + 10.7·sin68° + 9.1·sin72° ≈ 37 від осі + подушка (rx 11 + спрайт) → край ≈ 45–55; W ≈ 100–110 → W/P ≈ 1.09–1.20.
- *Повітря*: ярус #0 slot0 → подушка ≈ 35–49; наступний ярус того ж боку (k1) → ≈ 63–77 → зазор ≈ 14 units.
- *Бек-бадінг*: зона зрізу ≈ 6.8 ваги проти ≈ 4 решти гілки → ≈ 70% пагонів гілки біля зрізу (AC15 ≥ 50%).
- *RNG*: 8/18 без змін; темп (rate, кандидати) без змін.

**Ризики:**
1. IoU 0.80 з мальованим референсом — високий поріг: процедурні подушки мусять збігтися за положенням і розміром. Пом'якшення — діапазони тонування вище; якщо фікстура після тонування < 0.80, GP приносить CSV/PNG, GD вирішує (не знижувати поріг самостійно).
2. Затримка стовбура зсуває ранні пагони в яруси → можливий раніший «кущ» на Д10–Д20; перевірити AC17 і PNG Д20.
3. Бек-бадінг ×6 + стилізація кожні 10 діб → подушки можуть надмірно ущільнитись (N Styled > 150) і злипатись по вертикалі; контроль — AC3 (компоненти маски), `BackBudWeightMultiplier` у діапазоні.
4. `InPad` змінює розподіл ролей → темп; AC17.
5. Фіксований горщик 92: на Д0–Д10 дерево мале в кадрі — питання камери (UA), не моделі.
6. Дзеркальні дерева (`TierPhase = −1`) — IoU рахується з дзеркалом; без цього половина сидів «провалює» AC1.

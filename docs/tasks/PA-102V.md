## User story
Як власник/геймдизайнер, я хочу відкрити сцену в Unity Editor і прокрутити ріст дерева день за днем для різних порід, сидів і погоди, щоб оцінити форму і темп росту до появи справжнього рендеру (PA-103).

- [x] AC2. Збірка `PocketArbor.DevTools` (`Assets/_Project/Scripts/DevTools/`): references лише `PocketArbor.Domain`, `defineConstraints: UNITY_EDITOR` → у плеєр-білд не потрапляє; `LayerDependencyTests` перевіряє, що жодна runtime-збірка на неї не посилається.

## Технічний план / рішення
- `GrowthPreviewModel` — чистий replay: день 0 = `PlantSapling` + зняття Freeze Guard; день d = день d−1 + 24 год сталої погоди + зрізи, записані на день d. Зрізи зберігаються як (день, id), тож повзунок назад/вперед відтворює їх детерміновано; зміна параметрів скидає зрізи.
- `TreePreviewMeshBuilder` — один `Mesh` (UInt32 індекси, вертекс-кольори), шейдер `Universal Render Pipeline/2D/Sprite-Unlit-Default` (fallback `Sprites/Default`). У Linear-проєкті вертекс-кольори переводяться в linear, щоб hex з BALANCE виглядали як задумано.
- `GrowthPreviewController` (`[ExecuteAlways]`) — дерево видно й без Play (налаштування в інспекторі); IMGUI-панель — лише в Play.
- `GrowthPreviewEditorTools` — меню **Pocket Arbor → Dev → Create Growth Preview Scene** і batch-захоплення PNG (`-executeMethod PocketArbor.DevTools.GrowthPreview.GrowthPreviewEditorTools.CaptureBatch -captureOut <dir>`).
- Тести — окрема збірка `PocketArbor.DevTools.Tests` (`Tests/PlayMode/DevTools/`, constraints `UNITY_INCLUDE_TESTS` + `UNITY_EDITOR`).

## Як запустити (власнику)
1. У відкритому Editor дочекатися імпорту, відкрити `Assets/_Project/Scenes/Dev/GrowthPreview.unity`.
2. Натиснути **Play**. Ліва панель: повзунок **Day**, кнопки −1/+1, порода, Seed/Random, погода, vigor, bend bias, **Cut random branch**.
3. Без Play: виділити об'єкт `GrowthPreview` і змінювати поля в інспекторі (Day, Species, Seed…).

## Спостереження для GD / PA-103
- Модель ADR-0003 кріпить усіх дітей на **кінчику** батька (немає позиції кріплення вздовж гілки), тому до 3 пагонів виходять з однієї точки, і крона виглядає як «віник» / парасолька з вузлами-розвилками. Якщо потрібні бічні гілки вздовж осі — потрібне нове поле (наприклад, `AttachT` ∈ [0, 1]) — питання до GD/Architect.
- Топологія (кількість вузлів по днях) однакова для всіх порід при тому самому seed — порода впливає лише на кути й кривину. Це відповідає §1.1.
- Листя для debug — 2 кружечки на вузол; на 200 вузлах крона щільна.

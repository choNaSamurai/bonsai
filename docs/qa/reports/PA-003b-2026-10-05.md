## 7. Висновки

**(а) Newtonsoft vs JsonUtility для ADR-0008.** Поки в проєкті Unity IAP 5 або Unity Localization, Newtonsoft уже в білді і наше використання коштує 0.03 МБ — за розміром байдуже. Але Newtonsoft — це ~4.2 МБ Android / оцінка ~8–10 МБ iOS install, які звільняються лише тоді, коли його не використовує **ніхто**. Рекомендація: формат збереження ADR-0008 будувати на `JsonUtility` (DTO з `[Serializable]`, полями, масивами; `schemaVersion` — поле) або власному бінарному форматі, **не** на Newtonsoft — щоб не закрити собі важіль у −4 МБ і заодно мати менше алокацій. Змінити рядок 13 ADR-0008 («JSON (Newtonsoft…)») — рішення через оркестратора/власника.

**(б) Vulkan+GLES3 vs GLES3.** GLES3-only заощаджує лише 0.36 МБ (1.3%) після URP-стрипінгу. Аргумент розміру слабкий — лишити Vulkan+GLES3 за замовчуванням і вирішувати в perf-спайку на пристроях; GLES3-only — резервний важіль, якщо треба протиснутися під межу.

**(в) Localization + Addressables.** −0.65 МБ Android окремо; разом із заміною IAP це передумова прибрати Newtonsoft (−5.6 МБ). Для гри з невеликим обсягом UI-тексту і 2–4 мовами пропоную власні таблиці рядків (ScriptableObject/CSV → масив за int-ключем, TMP fallback-шрифти) — це також прибирає Addressables із білд-пайплайна. Якщо власнику/дизайнеру потрібні Smart Strings, плюралізація, синхронізація з Google Sheets — Localization лишаємо, ціна 0.65 МБ прийнятна, але тоді Newtonsoft-важіль закритий назавжди. Потрібен вхід від game-designer/ui-ux-developer: кількість мов і рядків.

**(г) Що внести в репо (НЕ внесено):**
1. `Assets/_Project/Editor/ProjectSetup.cs` → `ConfigurePlayerSettings()` для iOS і Android:
   `PlayerSettings.SetIl2CppCodeGeneration(target, Il2CppCodeGeneration.OptimizeSize);` (−5.9 Android, найбільший пункт)
   `PlayerSettings.SetIl2CppCompilerConfiguration(target, Il2CppCompilerConfiguration.Release);` (явно, не Master)
   `PlayerSettings.Android.minifyRelease = true;` (R8, −2.6) — потрібна перевірка на пристрої, що consumer-proguard-правила Play Billing / Notifications / Unity працюють;
   `PlayerSettings.SplashScreen.show = false;` (UX/холодний старт, не розмір).
2. `UniversalRenderPipelineGlobalSettings.asset` (або в `ProjectSetup` через `GraphicsSettings.GetRenderPipelineSettings<URPShaderStrippingSetting>()`): `m_StripUnusedPostProcessingVariantsAndResources: 1`, `m_Strip2DUnusedVariants: 1` (і legacy-поле `m_StripUnusedPostProcessingVariants: 1`) — −1.8.
3. `Assets/_Project/link.xml` → вміст L1: прибрати R3, R3.Unity, UniTask; Newtonsoft звузити до конкретних типів (або прибрати повністю, якщо ADR-0008 переходить на JsonUtility); PocketArbor.* і VContainer лишити — −1.47. Оновити TD-011.
4. `Packages/manifest.json`: пряму залежність `com.unity.nuget.newtonsoft-json` прибрати, якщо ADR-0008 → JsonUtility (на розмір зараз не впливає, але прибирає спокусу). `com.unity.localization` — за рішенням (в). Unity IAP — див. п.5.
5. Новий ADR (пропоную ADR-0009 «Білінг: Unity IAP 5 vs тонкий нативний плагін») — оцінити заміну IAP на власний мінімальний плагін (StoreKit 2 + Play Billing Library з C#-фасадом і Editor-заглушкою, як в ADR-0007) або сторонній SDK з перевіркою його залежностей. Це єдиний шлях до Android ≤ 25 і iOS download ≈ 35 з продуктовим контентом.
6. ARCHITECTURE §10: оновити baseline (PA-101 tuned+L1 = 25.8 Android, iOS 57 install / ~43 download) і чесно позначити, що iOS-бюджети при поточному стеку недосяжні — потрібне рішення власника: або переглянути бюджети (реалістично для поточного стеку: Android ≤ 30, iOS download ≤ 48 / install ≤ 62), або прийняти п.5.

### 10.4. Ризики (рантайм не перевірено — немає пристроїв)
1. **R8 + Play Billing / Unity IAP / Mobile Notifications / Unity Java-частина.** Бібліотеки мають consumer ProGuard-правила, а Unity додає `proguard-unity.txt`; збірка пройшла, але рантайм не перевірено. На пристрої (release `.aab` через internal testing або `bundletool install-apks`): ініціалізація IAP (`StoreController().Connect()`), запит продуктів, тестова покупка + acknowledge, Restore; планування і показ локальної нотифікації, тап по ній (відкриває застосунок); `adb logcat` без `ClassNotFoundException`/`NoSuchMethodError`. Якщо впаде — keep-правила в `Assets/Plugins/Android/proguard-user.txt` (Custom Proguard File), не вимикати R8.
2. **Звужений `link.xml` + VContainer / R3 / UniTask.** VContainer збережено повністю; ризик — у R3/UniTask, якщо до них ходять рефлексією (ми — ні; UniTask PlayerLoop-інжекція — статичні типи). На пристрої: старт сцени `Main` (DI-граф `RootLifetimeScope` резолвиться, `targetFrameRate = 120`), `ReactiveProperty.Subscribe`, `UniTask.Delay` — без `MissingMethodException`/`ExecutionEngineException` в логах. Рекомендую PlayMode-смоук на IL2CPP-плеєрі (`-testPlatform Android`) у PA-403.
3. **URP Strip 2D Unused Variants** — стрипінг за аналізом сцен білда: тип 2D-світла (Point/Freeform/Sprite), якого немає в жодній сцені білда, але який створюється з коду, лишиться без варіантів шейдерів (рожеве/неосвітлене). Правило для TA/GP: кожен тип світла має бути в `Main.unity` (можна вимкненим).
4. Strip Unused Post Processing: використовувані ефекти мають бути у VolumeProfile проєкту (стрипінг за VolumeProfile-ами, не за сценами) — для додавання post-processing потрібен профіль-асет.
5. Тест-прогін у batchmode без `-buildTarget` перемкнув у `ProjectSettings.asset` прапорець iOS Graphics API `m_Automatic` 0 → 1 (Metal лишився єдиним API, тож ефекту немає); `ProjectSetup` повертає 0. Перед комітом — прогнати `ProjectSetup` і переконатися, що в diff його немає.

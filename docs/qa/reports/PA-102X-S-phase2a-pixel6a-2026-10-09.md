- **Дата**: 2026-10-09
- **Гілка / стан**: `spike/PA-102X-S-render` @ b26d837 + незакомічені зміни в `.agent-workspace/pa102xs/src/` (A1–A3, див. «Зміни коду»)
- **Тестувальник**: Unity Architect (агент)

**Як міряли K1.** `FrameTimingManager.gpuFrameTime` на Mali непридатний: GLES3 для порожнього кадру повертає ~10⁸ мс, а Vulkan у steady-state показує 14–16.5 мс для будь-якого вмісту, бо DVFS знижує частоту GPU під 60 Гц. Тому K1 — це GPU-обмежений цикл: 90 кадрів прогріву частот, далі 3 × 60 рендерів сцени в RT розміру екрана з однією синхронізацією наприкінці, частини вмикаються по черзі. На Vulkan повтори стабільні (±10 %), на GLES3 — ні. Це вартість на піднятих частотах; у реальному 60 Гц-кадрі GPU працює повільніше, але з запасом.

## Трикутники й рекомендація щодо LOD / бюджету
- quality: деревина + ґрунт 129–134 тис. трикутників (t=1), горщик 56–68 тис.; budget: деревина 68 тис.
- **budget проти quality** (Vulkan, деревина): Момідзі 2.03 → 1.56 мс, Куромацу 3.88 → 2.83 мс, тобто −0.5…−1.0 мс; візуально IoU −0.3 % (фаза 1), на пристрої — та сама картинка. Удвічі менше вершин також удвічі зменшує пам'ять мешів і обсяг запікання.
- **Вартість деревини визначає фрагментний шейдер кори, а не трикутники.** Куромацу (Вороной на 27 комірок × 4 вибірки для рельєфу) удвічі дорожчий за Момідзі при однаковій кількості трикутників.
- **Рекомендація.** Узяти **budget (≈ 70 тис.) за замовчуванням**, а бюджет ADR-0011 «20–35 тис.» **переглянути вгору до ≈ 70 тис.**: подальше зменшення трикутників дає вже сотні мікросекунд. Головні заходи для mid/low-tier — у фрагменті:
  - дешевша кора Куромацу на LowEnd (менше вибірок Вороного, рельєф без 4-кратної вибірки, або запечені текстури кори);
  - процедурний горщик замінити параметричним мешем (≈ 5 тис. трикутників замість 56–68 тис.).
  
  LOD гілочок (оцінка −15–20 тис.) — лише якщо K1 на Adreno 618 / Mali-G57 це підтвердить.

## K4: скільки кадрів
- Геометрія без гілки — у наступному кадрі. Світло — через 8 або 24 кадри (за N).
- Запікання деревини на пристрої, вимір по проходах із синхронізацією: Surf 29–36, Snap 10–15, Light 27–34, Mat 6–8 мс, разом ≈ 80–90 мс на 67 тис. вершин. У синхронному показі — 90–140 мс.
- Через DVFS кадр у steady-state уже займає ≈ 14–16 мс GPU на знижених частотах, тож навіть слайс у 4 мс пропускає vsync. Тому без провалів потрібно:
  - **перезапікати лише вершини поруч зі зрізом** — у тіні прибраної гілки й біля стику, < 20 % вершин;
  - **снапити лише вершини поблизу стиків** (CPU-широка фаза): Surf стане в рази дешевшим;
  - нарізати слайси по ≤ 1.5–2 мс, тобто N ≈ 30–50 кадрів (0.5–0.8 с). Це сумісно з анімацією падіння (0.35 с) лише частково, тож рішення власника «N ≤ 8» без перших двох кроків не досягається.

## Інше, знайдене на пристрої
- **Unity 6 за замовчуванням вимикає Vulkan на Pixel 6/6 Pro/6a** (вбудований фільтр `google` / `oriole|raven|bluejay`; лог: «Vulkan API denied by user filter»). Порожній список заборон його не знімає, потрібне явне правило дозволу (зроблено лише в копії для K11). У проєкті API Android — Vulkan + GLES3, тож гравці з Pixel 6 отримають GLES3; K11 показує, що картинка однакова.
- Синхронне запікання горщика (Surface Nets) на пристрої — 220–380 мс (перший раз ≈ 0.95 с). Ще один аргумент за параметричний горщик.
- Алокації генератора в Хроніці: ~115–145 КБ/кадр → GC-стоп 0.3–0.4 с. Джерело — переважно `SketchGenerator.Scene` (GP); у моєму `BuildBack` теж є дрібниці (`Stopwatch`, `SpeciesLook`, рядок ключа горщика).

## Ризики
- Числа — з сильнішого за mid-tier пристрою. Adreno 618 / Mali-G57 не виміряно, і K1 для Куромацу там, за оцінкою, вище цілі.
- Повне перезапікання після зрізу або росту на mid-tier буде в рази повільнішим (80–90 мс на Mali-G78 при піднятих частотах).
- Пам'ять K8 без змін (подвійні буфери, вхідні текстури запікання, горщик) — 2.5× понад ціль.
- Прогрів PSO на Vulkan (≈ 0.6 с) обов'язковий (`GraphicsStateCollection`) — інакше підвисання при першому показі.
- `RGBA32F`/`RGBA16F` render targets і texel fetch у вершинному шейдері працюють на Mali-G78 (GLES 3.2, Vulkan). На старіших GLES 3.0 не перевірено.

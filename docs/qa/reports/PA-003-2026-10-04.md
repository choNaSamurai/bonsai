# PA-003 Spike: baseline розміру білда і холодний старт (Unity 6000.6.4f1, URP 2D)

> Автор: Unity Architect · 2026-10-04 · Статус: результати спайку (не ADR)
> Середовище: macOS, Unity 6000.6.4f1 (Personal), Android/iOS модулі, Xcode 26.2, bundletool 1.17.2 (з Unity AndroidPlayer/Tools), OpenJDK Temurin 17.0.18 (з Unity). Фізичних пристроїв немає.
> Усі розміри — у **MB = 10^6 байт** (як у сторах).

## 1. Що зібрано

Сцена: ортографічна камера (+`UniversalAdditionalCameraData`), 1 SpriteRenderer (64x64), Canvas + TMP-текст (LiberationSans SDF з TMP Essentials), EventSystem + `InputSystemUIInputModule`, `StartupProbe` (лог часу першого кадру). Active Input Handling = Input System only. Linear color space.

Спільні налаштування (якщо не вказано інше): IL2CPP, ARM64 only, Managed Stripping **High**, **Strip Engine Code**, IL2CPP Code Generation **OptimizeSize**, C++ config **Release**, non-development, stack trace None для Log/Warning, Android: AAB, ASTC, R8 minify, minSdk 29; iOS: target 16.0, Metal.

Проєкти (у теці спайку):
- **A (minimal)** — `manifest.json`: URP 17.6.0, ugui 2.6.0 (вкл. TMP), inputsystem 1.20.0, 2d.sprite, + модулі androidjni/audio/imageconversion/jsonserialize (решта — лише транзитивні залежності: ui, imgui, uielements, physics, physics2d...).
- **B (default modules)** — дефолтний набір `com.unity.modules.*` з `-createProject` (ai, cloth, terrain, vehicles, video, wind, xr, umbra, tilemap, unitywebrequest*, ...) + ті самі пакети.
- **C (діагностика, Built-in RP)** — як A, але без URP. Не варіант для продукту (Built-in RP deprecated з Unity 6.5), лише щоб виміряти «ціну» URP.

Метрики:
- **Android .aab** — розмір файлу. **Download arm64** — `bundletool build-apks` + `get-size total --device-spec` (arm64-v8a, 480 dpi, API 34). Для одного ABI MIN=MAX, тож це і є оцінка Play download size.
- **iOS .app** — розмір `.app` з `xcodebuild archive` (Release, generic iOS device, `CODE_SIGNING_ALLOWED=NO`) — це ≈ install size. **zip** — `zip -9` Payload (нижня межа download). **Оцінка App Store download** — zip ресурсів + сирий розмір Mach-O (App Store шифрує `__TEXT`, тож код майже не стискається) — верхня межа. App Thinning/реальний розмір App Store Connect не відтворено (немає підпису/акаунта) — це **оцінка**.

## 4. Які налаштування дають найбільший ефект

Від найбільшого (Android download, MB):
1. **URP vs Built-in: Android ~6.0 download; iOS +13.6 .app / ~+10 оцінки download** — ціна URP (Core+URP+GPUDriven+UIElements+Burst+Collections). Built-in RP deprecated з Unity 6.5 → не варіант; приймаємо як ціну стеку.
2. **Strip Engine Code: −4.9** (на Android теж працює — `libunity.so` 29.7 → 18.7 МБ нестиснуто).
3. **IL2CPP Code Generation = OptimizeSize: −3.7** (`libil2cpp` 37.3 → 19.2 МБ нестиснуто). Ціна — трохи повільніший код дженериків; для нашого навантаження некритично, але перевірити в perf-спайку.
4. **Managed Stripping High vs Minimal: −2.9.**
5. **URP-стрипінг (global settings: Strip Unused Post Processing Variants & Resources, Strip 2D Unused Variants; Renderer2D без PostProcessData): −1.3** (прибирає FilmGrain-текстури, Light2D-шейдер, SSR/debug-варіанти).
6. **Graphics API: GLES3 only −0.87 / Vulkan only −0.25** (шейдери під один бекенд).
7. **Мінімальні модулі в manifest: −0.74** (Terrain, XR, Tilemap, SpriteShape, Tetgen, Analytics, Subsystems...). Менший ефект, ніж очікувалось, бо Strip Engine Code уже прибирає невикористане; але різниця реальна і безкоштовна.
8. **Application Entry = Activity: −0.53** (без GameActivity: менший dex і без `libgame.so`).
9. **C++ Master (LTO): +1.3 — шкодить розміру**, лишаємо Release.
10. Splash off: 0 за розміром (логотип пакується все одно, Personal), але корисно для холодного старту/UX.

## 6. Рекомендації для ADR-0001 / ARCHITECTURE §10

**Пропоновані нові бюджети** (метрика вказується явно):
- Android: **Play download size arm64 ≤ 25 МБ** (bundletool `get-size total`), жорстка межа 30; `.aab` — інформативно.
- iOS: **App Store download size ≤ 35 МБ** (App Store Connect → TestFlight build → App Store File Sizes, або Xcode Organizer App Thinning Size Report), install ≤ 55 МБ.
- Довідково: Google Play оцінював −1% конверсії інсталу на кожні +6 МБ APK (стаття Google Play «Shrinking APKs, growing installs») — тобто різниця 20 vs 25 МБ ≈ 1% конверсії, а не прірва.

**Обов'язкові налаштування збірки (фіксувати в ADR-0001 / §10 і в Editor-скрипті перевірки):**
- IL2CPP, ARM64 only, Managed Stripping **High** + `link.xml`, **Strip Engine Code**, IL2CPP Code Generation **OptimizeSize**, C++ config **Release** (не Master — LTO збільшує розмір на ~1.3 МБ).
- URP Global Settings: `Strip Unused Post Processing Variants And Resources = on`, `Strip 2D Unused Variants = on`, `Strip Unused Variants = on`, `Strip Runtime Debug Shaders = on`; Renderer2D без `PostProcessData`, якщо пост-процес не потрібен (якщо потрібен — лише конкретні ефекти, не FilmGrain).
- Мінімальний `manifest.json` (як у проєкті A) — у PA-101 скафолдингу.
- Splash: вимкнути Unity-логотип (Unity 6 дозволяє на Personal) — заради холодного старту, не розміру.
- Graphics API Android: **окреме рішення** (GLES3 only = −0.9 МБ, найпростіше; Vulkan дає кращий CPU-оверхед на нових пристроях). Пропоную GLES3 only для MVP, переглянути після perf-спайку на пристроях.
- Application Entry: Activity −0.5 МБ, але GameActivity — рекомендований Unity шлях (краща інтеграція вводу/IME). Пропоную лишити GameActivity, доки бюджет не тисне; вирішити в ADR-0007.
- Не додавати Newtonsoft.Json без потреби (оцінка +1–1.5 МБ коду); для ADR-0008 — `JsonUtility`/власний бінарний формат.
- **CI-гейт**: після білда — BuildReport + `bundletool get-size total --device-spec arm64` з порогом; для iOS — .app size і `__TEXT` з `size -m`.
- Не форкати URP заради вирізання UIElements (найбільший шматок коду) — висока ціна підтримки; повернутися лише якщо бюджет стане блокером.

## 7. Холодний старт — не виміряно (немає пристроїв)

Відомі орієнтири:
- Unity на Android сама викликає `Activity.reportFullyDrawn` при завантаженні першої сцени (до `Awake`); якщо гра стає інтерактивною пізніше — викликати `DiagnosticsReporting.CallReportFullyDrawn` вручну ([Unity Manual: Optimize application startup times](https://docs.unity3d.com/6000.3/Documentation/Manual/android-optimize-application-startup.html)).
- Apple: ціль — перший кадр за ~400 мс ([WWDC19 Optimizing App Launch](https://developer.apple.com/videos/play/wwdc2019/423/), [Reducing your app's launch time](https://developer.apple.com/documentation/xcode/reducing-your-app-s-launch-time)). Для Unity-гри це недосяжно; реалістичні оцінки з форумів — 1–3 с до першого кадру гри на mid-tier (неофіційно, [Unity Discussions: Slow app startup time on iOS with Unity 6](https://discussions.unity.com/t/slow-app-startup-time-on-ios-with-unity-6/1539404), [Optimise game startup time](https://discussions.unity.com/t/optimise-game-startup-time/918146)). Гіпотеза ARCHITECTURE §1 (1.5–2.5 с) лишається гіпотезою.

План вимірювання (PA-003b, коли будуть пристрої; білд A9/A tuned уже містить `StartupProbe`, що логує `PA003_FIRST_FRAME t=<realtimeSinceStartup>`):
- **Пристрої**: Android low-mid (напр. Galaxy A1x/A3x, Android 10–12) + flagship; iPhone 11/SE 2 (нижня межа iOS 16) + iPhone 15.
- **Android**: release-білд (не development), `adb shell am force-stop <pkg>` → `adb shell am start -W -n <pkg>/<activity>` × 10, медіана `TotalTime` (TTID) і `WaitTime`; паралельно `adb logcat -s ActivityTaskManager:I` → рядки `Displayed` і `Fully drawn` (TTFD = reportFullyDrawn), плюс `PA003_FIRST_FRAME` з `adb logcat -s Unity`. Для CI — Jetpack Macrobenchmark `StartupTimingMetric` (окремий тест-модуль, StartupMode.COLD). Перед вимірюванням: `adb shell cmd package compile -m speed-profile -f <pkg>` (як після Play-інсталу з Baseline/Cloud profiles) і окремо без компіляції.
- **iOS**: Xcode Instruments → шаблон **App Launch** (cold: перезавантаження пристрою або ≥ кілька інших застосунків між запусками), × 5, медіана до першого кадру; додатково `os_signpost` у native-плагіні на першому `Update` (через `StartupProbe` → DllImport) щоб бачити Unity-фазу; у полі — MetricKit `MXAppLaunchMetric` (histogrammedTimeToFirstDraw).
- **Розкласти час** на фази: pre-main / dylib (UnityFramework — великий), Unity engine init (`realtimeSinceStartup` на `SubsystemRegistration`), завантаження першої сцени, перший кадр. Profiler (development-білд, Deep profile off) з `-profiler-enable` на старті.
- **Варіанти для порівняння**: splash on/off, GLES3 vs Vulkan, GameActivity vs Activity, пуста bootstrap-сцена + асинхронне завантаження основної.
- **Критерій**: TTID і «перший інтерактивний кадр» — медіана і p90; ціль ставиться після вимірювання (пропоную стартову ціль ≤ 2.0 с mid-tier, ≤ 1.2 с flagship).

## 8. Що не вдалося / обмеження
- Холодний старт — немає пристроїв.
- Реальний App Store download/install size — немає підпису/акаунта App Store Connect; App Thinning Size Report вимагає export з підписом. Наведено межі й оцінку.
- Play download size — оцінка bundletool (gzip-модель), реальний Play може відрізнятися на ±5–10% (Play застосовує власні компресії/патчі).
- Вплив VContainer/R3/UniTask/PrimeTween не вимірювався (пакети не в scope спайку) — прогноз у §5 є оцінкою; рекомендую повторити вимірювання після PA-101 (той самий скрипт).
- Сплеш-логотип Unity пакується навіть із `SplashScreen.show = false` (Personal) — ~0.1 МБ стиснуто, неважливо.
